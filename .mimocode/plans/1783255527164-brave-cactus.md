# 权限模型重构后续工作计划

## 计划概述

基于对抗式审查发现的问题，制定修复工作完善与需求进一步实现两部分工作计划。

## 一、修复工作完善（遗留问题）

### 1.1 错误码注册（P1 · 0.5h · 低复杂度）

**原问题：** `INTERNAL_ERROR` 和 `INVALID_REQUEST_BODY` 两个错误码在 `app.py` 全局异常处理器中直接使用，但未在 `error_codes.py` 的 `ERROR_CODES` 字典中注册。当前不影响运行，但破坏了前端基于 code 做统一映射的能力。

**根因：** API规范定义了14个错误码，但 `error_codes.py` 只注册了12个，遗漏了2个。

**解决方案：**
在 `backend/app/gateway/error_codes.py` 的 `ERROR_CODES` 字典末尾添加：
```python
"INTERNAL_ERROR": {
    "status_code": 500,
    "message": "服务器内部错误",
},
"INVALID_REQUEST_BODY": {
    "status_code": 400,
    "message": "请求体格式不合法",
},
```

**验证方法：** 运行现有测试确认无回归，检查 `ApiException("INTERNAL_ERROR")` 不再抛出 ValueError。

---

### 1.2 Skill 导出/导入端点（P0 · 4h · 中等复杂度）

**原问题：** API规范定义了 `GET /api/skills/{id}/export` 和 `POST /api/skills/import` 端点，但代码中不存在。

**根因：** 迁移方案中Phase 5（后端代码重构）未完整实现所有API端点。

**解决方案：**
参照 `agents.py:809-919` 已有的 export/import 设计，在 `backend/app/gateway/routers/skills.py` 新增两个端点：

1. **导出端点** `GET /api/skills/custom/{skill_name}/export`
   - 返回 JSON bundle 含 SKILL.md 原文和 metadata
   - 权限：按 visibility 过滤

2. **导入端点** `POST /api/skills/custom/import`
   - 接收内容写入 custom skill 目录
   - 创建 resource_metadata 记录
   - 调用 `scan_skill_content` 进行安全扫描

**验证方法：** 编写单元测试覆盖导出/导入流程，验证权限控制正确。

---

### 1.3 Workflow 导出/导入端点（P0 · 3h · 中等复杂度）

**原问题：** API规范定义了 `GET /api/workflows/{id}/export` 和 `POST /api/workflows/import` 端点，但代码中不存在。

**根因：** 同1.2，迁移方案未完整实现。

**解决方案：**
在 `backend/app/gateway/routers/workflows.py` 新增两个端点：

1. **导出端点** `GET /api/workflows/{name}/export`
   - 返回 YAML + metadata
   - 权限：按 visibility 过滤

2. **导入端点** `POST /api/workflows/import`
   - 用 `parse_workflow_string()` 校验格式
   - 存储到 workflow_store
   - 创建 resource_metadata 记录

**验证方法：** 编写单元测试覆盖导出/导入流程，验证重名检测逻辑。

## 二、需求进一步实现（功能缺失）

### 2.1 列表页 visibility 标签与搜索（P1 · 3h · 低复杂度）

**原问题：** workflow/agent列表页缺少visibility标签、搜索功能，用户无法直观看到资源的可见性状态。

**根因：** 后端已返回 visibility 数据（类型定义已包含），但前端UI未渲染。

**解决方案：**
1. **visibility标签**：在 `workflow-card.tsx` 和 `agent-card.tsx` 的标题区域增加彩色Badge
   - private = 灰色
   - department = 蓝色
   - public = 绿色

2. **搜索功能**：在 `workflow-gallery.tsx` 和 `agent-gallery.tsx` 头部加 Input 组件
   - 纯前端按 name/description 过滤
   - 无需后端改动

**文件：**
- `frontend/src/components/workspace/workflows/workflow-card.tsx`
- `frontend/src/components/workspace/workflows/workflow-gallery.tsx`
- `frontend/src/components/workspace/agents/agent-card.tsx`
- `frontend/src/components/workspace/agents/agent-gallery.tsx`

**验证方法：** 手动测试筛选功能，验证不同visibility的Badge颜色正确。

---

### 2.2 部门删除资源重分配 UI（P1 · 5h · 中等复杂度）

**原问题：** 部门删除时缺少前端资源重分配UI，当前仅用浏览器confirm弹窗，后端静默降级department级资源为private。

**根因：** 前端未实现资源重分配交互，后端 `admin.py:799-807` 静默处理。

**解决方案：**
1. **新增后端端点** `GET /api/admin/departments/{id}/resources`
   - 返回受影响资源列表
   - 权限：super_admin

2. **修改删除端点** `DELETE /api/admin/departments/{id}`
   - 增加可选参数 `target_dept_id`
   - 有值时更新 department_id 而非降级 visibility

3. **前端重分配UI**
   - 点击删除先调用新端点获取受影响资源
   - 弹出对话框展示资源列表
   - 提供"重分配到目标部门"下拉框或"降级为私有"选项
   - 确认后带 `target_dept_id` 参数调用 DELETE

**文件：**
- `backend/app/gateway/routers/admin.py`
- `frontend/src/app/workspace/admin/departments/page.tsx`
- `frontend/src/core/admin/api.ts`

**验证方法：** 手动测试部门删除流程，验证资源重分配逻辑正确。

---

### 2.3 收藏功能（P2 · 5h · 中高复杂度）

**原问题：** workflow/agent列表页缺少收藏功能，用户无法快速访问常用资源。

**根因：** 收藏功能未在迁移方案中定义，属于新增功能。

**解决方案：**
1. **数据库变更**：在 `resource_metadata` 表新增 `is_favorited` 列（BOOLEAN, DEFAULT FALSE）
2. **新增API端点**
   - `POST /api/workflows/{name}/favorite` - 切换收藏状态
   - `POST /api/agents/{name}/favorite` - 切换收藏状态
3. **前端UI**
   - 在卡片上添加星标按钮
   - 在gallery头部添加"仅显示收藏"筛选器

**文件：**
- `backend/app/gateway/routers/workflows.py`
- `backend/app/gateway/routers/agents.py`
- `frontend/src/components/workspace/workflows/workflow-card.tsx`
- `frontend/src/components/workspace/agents/agent-card.tsx`

**验证方法：** 编写单元测试覆盖收藏切换逻辑，验证权限控制正确。

**注意：** 建议拆为独立迭代，不阻塞其他P0/P1项。

**原问题：** admin/tools页面缺少visibility管理列，用户无法在管理后台直观看到工具的可见性状态。

**根因：** 迁移方案要求"增加tool visibility管理列"，但前端实现时遗漏了该功能。

**解决方案：**

1. 从后端API获取工具的visibility字段（需确认后端已返回）
2. 在工具信息区域添加visibility Badge显示
   - private = 灰色
   - department = 蓝色
   - public = 绿色
3. 保持只读，不提供修改功能（Tool的visibility变更通过审批流程）

**文件：**
- `frontend/src/app/workspace/admin/tools/page.tsx`
- `frontend/src/components/workspace/tools/`（如有工具卡片组件）

**验证方法：** 手动测试，验证不同visibility的Badge颜色正确显示。

### 2.5 skill-settings页面改为只读列表（P2 · 0.5h · 低复杂度）

**原问题：** skill-settings-page.tsx仍包含visibility申请对话框功能，与需求文档"删除（功能移除），改为只读列表"不一致。

## 四、风险评估

### 低风险
- **1.1 错误码注册**：改动面小，无跨模块依赖
- **2.1 visibility标签+搜索**：仅前端UI改动，无后端变更
- **2.4 admin/tools visibility列**：仅前端UI改动，添加只读显示
- **2.5 skill-settings只读改造**：删除对话框代码，保留列表展示

### 中风险
- **1.2 Skill导出/导入**：导入功能需要处理并发写入和文件系统竞态，建议加文件锁
- **1.3 Workflow导出/导入**：同上，需依赖已有的storage层并发控制
- **2.2 部门删除重分配**：涉及后端DELETE端点行为变更，需保证向后兼容

### 中高风险
- **2.3 收藏功能**：需新增数据库列和API端点，影响范围较大
