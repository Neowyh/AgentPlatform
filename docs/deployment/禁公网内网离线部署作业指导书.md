# DeerFlow 禁公网内网离线部署作业指导书

## 1. 目的

在无法访问公网的企业内网中，使用离线 `tar` 包部署当前版本 DeerFlow，并保持模型服务地址等运行配置可单独修改。

## 2. 适用范围

- 目标架构：`x86_64/amd64`
- 部署模式：本地沙箱模式
- 交付方式：离线镜像包 + 源码包
- 运行方式：`docker compose`

## 3. 构建机前置条件

- 已安装 Docker 和 Docker Compose v2
- 可访问本地或企业镜像仓库以拉取基础镜像
- 当前工作目录为 DeerFlow 仓库根目录
- 当前用户可以访问 Docker daemon

检查命令：

```bash
docker version
docker compose version
docker info
```

如果 `docker info` 报 `permission denied while trying to connect to the docker API at unix:///var/run/docker.sock`，说明当前用户没有 Docker socket 权限。可选修复方式：

```bash
sudo systemctl start docker
sudo usermod -aG docker "$USER"
```

执行 `usermod` 后需要退出当前登录会话并重新登录，再重新执行 `docker info`。如果只是临时打包，也可以使用：

```bash
sudo -E scripts/package-intranet-offline.sh --version 20260521-intranet --force
```

## 4. 一键打包

执行以下命令生成离线包：

```bash
cd /path/to/deer-flow
scripts/package-intranet-offline.sh --version 20260521-intranet
```

可选参数：

- `--force`：覆盖同版本输出目录
- `--no-cache`：强制重新构建镜像
- `--require-clean`：要求 Git 工作区干净
- `--output-dir`：自定义输出目录

生成结果默认位于：

```text
dist/intranet/deer-flow-20260521-intranet/
```

## 5. 离线包内容

离线包中至少包含：

- `deer-flow-images-<version>.tar`
- `deer-flow-source-<version>.tar.gz`
- `docker-compose.intranet.yaml`
- `env.intranet.example`
- `deploy-intranet.sh`
- `MANIFEST.txt`
- `SHA256SUMS`

## 6. 内网服务器准备

在内网服务器上建立部署目录，例如：

```bash
mkdir -p /opt/deer-flow
cd /opt/deer-flow
```

解压离线包后，目录里会出现：

- `source/`：展开后的 DeerFlow 源码
- `runtime/`：运行配置目录
- `env.intranet`：部署环境变量

首次部署时，脚本会自动补齐这些运行配置文件：

- `runtime/config.yaml`
- `runtime/.env`
- `runtime/frontend.env`
- `runtime/extensions_config.json`

如果要手工准备，也可以先编辑这些文件再启动。

`env.intranet.example` 只是参考模板，`prepare` 命令会按当前 bundle 路径自动生成 `env.intranet`。

## 7. 导入镜像

把离线包传到内网服务器后，执行：

```bash
docker load -i deer-flow-images-20260521-intranet.tar
```

验证镜像已导入：

```bash
docker images | grep deer-flow
docker images | grep nginx
```

## 8. 启动服务

先准备部署环境变量文件：

```bash
./deploy-intranet.sh prepare
```

然后启动服务：

```bash
./deploy-intranet.sh up
```

查看状态：

```bash
./deploy-intranet.sh status
```

查看日志：

```bash
./deploy-intranet.sh logs gateway
./deploy-intranet.sh logs frontend
./deploy-intranet.sh logs nginx
```

访问地址：

```text
http://<内网服务器IP>:2026
```

## 9. 修改模型服务地址

`config.yaml` 中的模型服务地址可以单独修改，不需要重新打包镜像。

修改后只重启 gateway：

```bash
./deploy-intranet.sh restart
```

## 10. 重复打包

如果要重新打包同一版本，建议：

```bash
scripts/package-intranet-offline.sh --version 20260521-intranet --force
```

如果底层依赖发生变化，建议：

```bash
scripts/package-intranet-offline.sh --version 20260521-intranet-r2 --no-cache
```

## 11. 回滚

保留上一版本镜像包和源码包。

回滚时只需：

1. 重新 `docker load` 上一版本镜像
2. 把 `env.intranet` 中的镜像版本改回旧版本
3. 执行 `./deploy-intranet.sh restart`

## 12. 常见故障

- `docker load` 失败：检查镜像包是否完整，先核对 `SHA256SUMS`
- 打包时报 Docker socket `permission denied`：先执行 `docker info` 验证权限；将当前用户加入 `docker` 组并重新登录，或临时用 `sudo -E` 执行打包脚本
- `frontend` 启动失败：确认 `frontend/.env` 存在
- `gateway` 启动失败：确认 `config.yaml` 和 `extensions_config.json` 路径正确
- 页面打不开：确认 `PORT` 未被占用，且 `nginx` 容器已启动
- 登录态失效：确认 `BETTER_AUTH_SECRET` 固定不变
