## 一、需求覆盖情况

从 5 份设计文档中提炼出 129 条需求，分 8 个类别逐一与代码对照。

### A. 数据库/模型层（16 条需求）— 全部通过

- resource_metadata 表：11 个字段、唯一约束、5 个索引、外键约束均与设计文档一致
- visibility_applications 表：15 个字段、pending 条件唯一索引、乐观锁 version 均已实现
- 旧表 skill_applications 已标记废弃（端点返回 410），skill_default_configs 和 user_skill_preferences 无 ORM 模型

### B. 权限检查（16 条需求）— 全部通过

- check_resource_access 按 visibility 五级规则执行，无 admin 隐式权限
- check_resource_modify 仅检查 owner，super_admin 不再有跨用户编辑权
- skills.py / agents.py 中的重复函数（_check_resource_modify、_is_visible_to_user、_can_set_visibility）均已删除
- update_skill_visibility 端点已移除

### C. API 端点（32 条需求）— 30 通过，2 部分实现

**通过的部分：**
- skill/agent/workflow CRUD 统一读写 resource_metadata
- visibility-applications 四个端点（提交/审批/撤回/列表）功能完整
- 旧 skill-applications 端点返回 410 Gone
- 通用响应格式 {success, data, error: {code, message}} 已统一

**已修复的问题：**
- ✅ skill/agent 删除后软删除 resource_metadata（skills.py:433-443, agents.py:752-761）
- ✅ 审批通过后自动更新 resource_metadata.visibility（visibility_applications.py:257-268）

### D. 资源生命周期（15 条需求）— 全部通过

- 调岗降级：update_user 中 department 变更时自动将 department 级资源降为 private
- 禁用用户：TRANSFER_REQUIRED 检查 + 自动驳回申请人 pending + 重分配审批人 pending
- 部门删除：降级 department 级资源 + 清理 department_id 引用
- 资源删除：skill/agent/workflow 删除时自动驳回 pending 申请

### E. 审批流程（11 条需求）— 全部通过

- 状态机 pending → approved/rejected/withdrawn 正确
- 同资源仅一个 pending（数据库唯一索引 + 代码双重检查）
- dept_admin 不可自审（applicant_id == current_user.id → 403）
- 资源删除自动驳回 pending 申请

### F. 并发控制（4 条需求）— 3 通过，1 部分实现

**通过的部分：**
- skill 和 workflow 编辑接口 version 为必填，不匹配返回 VERSION_CONFLICT
- 审批接口已有乐观锁校验

**遗留问题：**
- ⏳ agent 编辑接口 version 为可选（AgentUpdateRequest.version: int | None = Field(default=None)）
- 建议改为必填以与其他资源类型保持一致

### G. 错误码（14 条需求）— 12 通过，2 未实现

**通过的部分：**
- error_codes.py 定义 12 个标准错误码
- ApiException 类继承 HTTPException，携带 code 和 message
- app.py 注册三个全局异常处理器，统一返回格式

**遗留问题：**
- ❌ INVALID_REQUEST_BODY 错误码未定义
- ❌ INTERNAL_ERROR 错误码未定义

### H. 前端（21 条需求）— 审计范围内的 3 项通过

- skill-defaults 页面目录已删除
- visibility-applications 审批中心页面功能完整（筛选/分页/审核/撤回）
- skill-applications 页面自动重定向到审批中心

注：前端其余 18 条需求（收藏/置顶/搜索、visibility 标签、导出按钮等）属于 Phase 6 改造范围，本次审计未深入检查前端路由和组件。
