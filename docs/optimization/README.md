# iDeer 企业内网平台优化方案

## 概述

本文档描述 iDeer 平台 `offline_feature` 分支的后续优化方案。当前分支已完成 Phase 1-5 功能开发，但存在未合并的 Bug 和功能缺陷，需要在 PR 前修复。

**核心原则**：先修 Bug，再补测试，最后做性能和文档优化。

## 当前状态

| 维度 | 现状 | 目标 |
|------|------|------|
| Bug 状态 | 37 项遗留 + 本轮新发现 20+ 项 | P0/P1 全部清零 |
| 后端测试 | 211 个测试文件 | Admin/Workflow/Tools 模块补充测试 |
| 前端测试 | 8 个 E2E + 22 个单元测试 | Admin/Workflow 页面 E2E 覆盖 |
| 安全等级 | 基础（无限流、无审计） | 企业级 |
| 文档完整性 | 基础 README | API 文档 + 用户手册 + 部署指南 |

## 优先级矩阵

### 🔴 P0 — 必须在 PR 前修复

| 问题 | 工作量 | 说明 |
|------|--------|------|
| 工作流 goto 跳转失效 | 1-2 天 | 条件分支功能不可用 |
| Auth bypass 逻辑缺陷 | 0.5 天 | 安全漏洞 |
| RBAC 故障时权限升级 | 0.5 天 | 安全漏洞 |
| 前端 Admin 页面无角色校验 | 0.5 天 | 权限绕过 |

### 🟡 P1 — 本迭代必须完成

| 问题 | 工作量 | 说明 |
|------|--------|------|
| 后端 HIGH Bug（7 项） | 3-4 天 | MCP 竞态、表达式解析、持久化等 |
| 前端 HIGH Bug（4 项） | 2-3 天 | API 错误处理、Skill 保存、认证代理 |
| 测试补充 | 5-7 天 | Admin/Workflow/Tools 模块 |
| 安全加固 | 4-6 天 | 限流、输入验证、审计日志 |

### 🟢 P2 — 建议完成

| 问题 | 工作量 | 说明 |
|------|--------|------|
| API 文档 | 2-3 天 | Swagger/OpenAPI |
| 用户手册 | 4-5 天 | 使用指南 |
| 部署文档 | 2-3 天 | 内网部署指南 |
| 性能优化 | 3-4 天 | 索引、连接池、前端 |

## 总体工作量

- **P0（Bug 修复）**: 3-4 天
- **P1（测试 + 安全）**: 14-20 天
- **P2（文档 + 性能）**: 11-15 天
- **总计**: 28-39 天（约 1.5-2 个月）

## 实施顺序

```
第一阶段（第 1-3 周）：Bug 修复
├── 第 1 周：CRITICAL Bug（goto、auth bypass、权限升级）
├── 第 2 周：HIGH Bug（MCP 竞态、表达式、前端 API）
└── 第 3 周：MEDIUM Bug + 遗留问题

第二阶段（第 4-6 周）：测试补充
├── 第 4 周：Admin API 测试
├── 第 5 周：工作流集成测试
└── 第 6 周：前端 E2E 测试

第三阶段（第 7-10 周）：安全 + 文档
├── 第 7-8 周：安全加固（限流、验证、审计）
└── 第 9-10 周：文档建设

第四阶段（第 11-12 周）：性能 + 验收
├── 第 11 周：性能优化
└── 第 12 周：集成验收
```
