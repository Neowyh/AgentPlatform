# iDeer 内网源码导入取舍分析

日期：2026-05-25

## 结论

如果目标是“企业内网内做源码阅读、问题定位、二次开发和调试”，建议导入源码与锁文件，不导入本机依赖、构建缓存、运行数据和索引缓存。当前工作区实际体量约为：

- `frontend/`：约 3.3G，其中 `frontend/node_modules` 约 1.2G，`frontend/.next` 约 2.2G；源码和测试本身只有数 MB。
- `backend/`：约 952M，其中 `backend/.venv` 约 920M；后端源码、测试和锁文件本身约 9M。
- `.git`：约 1.6G；除非内网需要完整提交历史，否则不建议导入。
- `.gitnexus`：约 359M；属于本机代码索引缓存，不建议导入。

因此，源码分析调试包应以 `backend/`、`frontend/`、`scripts/`、`docker/`、`skills/`、必要文档和示例配置为主体。不要直接复制整个工作区。

## 必须导入

这些内容构成项目可读、可构建、可调试的主干：

- `backend/app/`：FastAPI 网关、认证、路由、渠道集成等后端入口代码。
- `backend/packages/`：`ideer-harness` 核心代理、模型、工具、MCP、沙箱、配置、持久化等逻辑。
- `backend/tests/`：后端回归测试，排查问题和验证改动需要。
- `backend/pyproject.toml`、`backend/uv.lock`、`backend/Makefile`、`backend/langgraph.json`、`backend/Dockerfile`：后端依赖、构建和运行定义。
- `frontend/src/`：Next.js 前端路由、组件、核心逻辑和样式。
- `frontend/public/`：前端静态资源，当前约 16M，属于运行界面需要的资源。
- `frontend/tests/`：前端单测和 E2E 测试。
- `frontend/package.json`、`frontend/pnpm-lock.yaml`、`frontend/next.config.js`、`frontend/tsconfig.json`、`frontend/playwright.config.ts`、`frontend/vitest.config.ts`、`frontend/Dockerfile`、`frontend/Makefile`：前端依赖、构建和测试定义。
- `scripts/`：安装、检查、部署、内网打包等项目脚本。
- `docker/`：Compose、Nginx、部署相关配置。
- `skills/public/`、`skills/custom/fault-zeroing/`、`skills-lock.json`：项目随仓库分发的技能和锁定信息。
- `config.example.yaml`、`extensions_config.example.json`、`.env.example`、`frontend/.env.example`：示例配置，只带 example，不带本机真实配置。
- `Makefile`、`README.md`、`README_zh.md`、`AGENTS.md`、`backend/AGENTS.md`、`frontend/AGENTS.md`：入口命令、说明和仓库协作约定。

## 建议导入

这些不是运行主路径的硬依赖，但对内网分析、故障复现和交接有价值：

- `docs/`：架构、部署、计划和故障归零相关材料。当前约 1M，体量很小，建议全量带入。
- `backend/docs/`：后端 API、认证、配置、流式输出、中间件等说明。
- `.github/workflows/`：CI 检查命令和测试矩阵，可作为内网流水线改造参考。
- `.pre-commit-config.yaml`、`.gitattributes`、`.gitignore`、`.dockerignore`：质量门禁和忽略规则。
- `CONTRIBUTING.md`、`Install.md`、`SECURITY.md`、`LICENSE`：合规、安装和贡献说明。
- `pr-build/`：当前只有少量截图，约 3.1M。若内网要复盘历史前端问题可带；否则可忽略。
- `.agent/skills/smoke-test/`、`.agents/skills/humanizer-zh/`：当前被 Git 跟踪，但不是主应用源码。若内网调试要复用这些本地 agent 技能，可以带；若只分析 iDeer 主体，可不带。

## 必须忽略

这些内容体量大、可重建、或包含本机状态，不应导入内网源码包：

- `.git/`：完整 Git 历史约 1.6G。只做源码分析时不需要；如需历史，可单独用 `git bundle` 或镜像仓库处理。
- `.gitnexus/`：GitNexus 本机索引缓存约 359M。进入内网后重新索引即可。
- `frontend/node_modules/`：约 1.2G，可由 `pnpm-lock.yaml` 重建。
- `frontend/.next/`：约 2.2G，Next.js 构建产物，可重建。
- `backend/.venv/`：约 920M，可由 `backend/uv.lock` 重建。
- `backend/.ideer/`：运行数据、用户/渠道数据，当前约 24M，不应作为源码导入。
- `logs/`、`log/`、`*.log`：运行日志。
- `temp/`、`dist/`、`frontend/test-results/`、`frontend/playwright-report/`、`coverage/`、`backend/.pytest_cache/`、`backend/.ruff_cache/`、`.ruff_cache/`、`__pycache__/`、`*.pyc`、`frontend/tsconfig.tsbuildinfo`：缓存、测试报告或临时产物。
- `.env`、`frontend/.env`、`config.yaml`、`mcp_config.json`、`extensions_config.json`：本机真实配置或密钥风险文件。只导入对应 `.example` 文件。
- `.vscode/`、`.idea/`、`*.swp`、`.DS_Store` 等 IDE/系统文件。

## 需要特别注意的风险

仓库已有 `scripts/package-intranet-offline.sh`，它会生成离线部署包，并在源码包里排除 `.git`、`backend/.venv`、`backend/.ideer`、`frontend/node_modules`、`frontend/.next`、`logs` 等大目录。这个范围适合作为“离线部署包”的基础。

但当前脚本在打包 `frontend` 整目录时没有显式排除 `frontend/.env`、`frontend/test-results/`、`frontend/playwright-report/`、`frontend/tsconfig.tsbuildinfo`。如果当前机器上存在这些文件，源码包可能带入本机配置或无用报告。建议打包前先清理，或补充排除规则。

## 推荐导入方式

### 源码分析调试包

适合内网做代码审查、调试、二次开发，但不包含预构建镜像和依赖缓存：

```bash
tar -czf /tmp/ideer-source-analysis.tar.gz \
  --exclude='.git' \
  --exclude='.gitnexus' \
  --exclude='dist' \
  --exclude='logs' \
  --exclude='log' \
  --exclude='temp' \
  --exclude='*.log' \
  --exclude='__pycache__' \
  --exclude='*.pyc' \
  --exclude='.ruff_cache' \
  --exclude='backend/.venv' \
  --exclude='backend/.ideer' \
  --exclude='backend/.pytest_cache' \
  --exclude='backend/.ruff_cache' \
  --exclude='frontend/node_modules' \
  --exclude='frontend/.next' \
  --exclude='frontend/test-results' \
  --exclude='frontend/playwright-report' \
  --exclude='frontend/tsconfig.tsbuildinfo' \
  --exclude='.env' \
  --exclude='frontend/.env' \
  --exclude='config.yaml' \
  --exclude='mcp_config.json' \
  --exclude='extensions_config.json' \
  backend frontend scripts docker docs skills \
  Makefile README.md README_zh.md AGENTS.md \
  config.example.yaml extensions_config.example.json skills-lock.json \
  .env.example .gitignore .dockerignore .pre-commit-config.yaml
```

### 禁公网离线运行部署包

如果内网不仅要分析源码，还要在无公网环境直接启动服务，应使用现有脚本生成完整离线部署包：

```bash
scripts/package-intranet-offline.sh --version <版本号> --force
```

该方式会额外构建并导出 Docker 镜像包，适合部署交付；但它依赖外网侧已经能拉取/构建依赖。进入内网后再构建依赖通常会受 PyPI、npm、镜像源限制。

## 建议的最小校验

打包前建议执行：

```bash
git status --short
find . -maxdepth 3 -type f \( -name '.env' -o -name 'config.yaml' -o -name 'extensions_config.json' -o -name 'mcp_config.json' \) -print
du -sh backend frontend .git .gitnexus 2>/dev/null
```

打包后建议在临时目录解压并确认：

```bash
tar -tzf /tmp/ideer-source-analysis.tar.gz | grep -E '(^|/)(node_modules|\.next|\.venv|\.git|\.gitnexus|\.env|config.yaml)$'
```

如果该命令没有输出，说明主要的大目录和敏感配置没有被带入。
