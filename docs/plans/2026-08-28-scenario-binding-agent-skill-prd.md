## Problem Statement

新对话页（登录后默认落地的工作台欢迎态）已提供三级场景化入口：场景 Tab（日常办公 / 创意设计 / 专业任务）→ 场景分组 Pill → 任务 Chip。当前这些入口**仅做文本注入**：点击 Chip 后把一条提示语模板填入输入框，依赖大模型自行猜测应调用何种能力。场景分组的标识与真实智能体无关，任务的技能名也未以结构化方式传递给后端，导致以下问题：

1. **命中不稳定**：同一技能被多个任务复用（如摘要），仅靠提示语中的自然语言区分，模型经常选错或不触发。
2. **无法确定性复用智能体**：智能体是长期人格与工具集的封装，但场景分组未与任何智能体实体绑定，用户无法通过场景入口稳定复用已配置好的智能体。
3. **智能体资产缺口**：12 个场景分组中仅 2 个拥有真实智能体实体，其余 11 个分组有技能无智能体，用户即使想绑定也无对象可绑。
4. **预装资源可见性不一致**：离线部署预装的 22 个技能、2 个智能体、1 个工作流未统一默认公开，新用户首次进入时部分入口绑定的资源不可见，需要额外授权。
5. **无运营能力**：场景与任务的绑定关系写死在前端代码中，运营或管理员无法在不发版的情况下调整“哪个分组对应哪个智能体、哪个任务对应哪些技能”。
6. **标签与命名割裂**：任务选中后无独立标签回显，用户无法直观确认当前任务；批量新建智能体的名称与前端分组显示名称不一致，增加认知负担。

从用户视角：站在点单台前，看到菜单却发现按按钮不会真的把对应的店员和机器叫过来，只能靠自己喊话让后厨猜。

## Solution

将场景化入口从“提示语助手”升级为“确定性绑定入口”，并一次性补齐缺口资产、统一预装可见性与运行时保障：

1. **结构化绑定**：选中场景分组时绑定一个智能体，选中任务时绑定一个或多个技能。提交消息时同时发送结构化上下文与提示语文本，后端确定性加载对应能力，不再依赖猜测。
2. **批量补齐智能体（名称对齐）**：为 11 个无实体分组按统一规范批量新建智能体，全部默认公开可见，开箱即用。智能体在构建时即按前端的 Pill→Chip→Skill 绑定关系设置其 `skills` 列表，使“分组→智能体→技能”链路在智能体层面闭环；**新建智能体的名称与展示名称对齐前端分组 Pill 的显示名称**，降低用户认知成本。
3. **预装可见性统一（清单不变）**：保持离线部署预装技能清单不变（22 技能 + 2 智能体 + 1 工作流），仅将所有预装资源的默认可见性统一设置为公开；新创建的资源仍默认私有、需审批后升级。
4. **可运营配置**：绑定关系持久化到数据库，超管可在管理后台修改分组与任务的绑定、提示语与启用状态，30 秒内对新对话生效；普通用户仅看到有权限的条目，无权限条目直接不展示。
5. **过滤式互斥**：智能体与技能弹窗是绑定的。选中分组（智能体）后，技能弹窗不消失，而是**仅展示与该智能体相关的技能**（即该智能体的 `skills` 列表）；未选分组时展示全部可用技能。取消选中后恢复全量。
6. **双标签回显**：场景分组与任务均在输入框内以可删除标签形式回显，任务标签样式参考分组标签但加以区分，且任务标签的展示与后台所选技能名称保持一致。
7. **运行时确定性保障**：通过“前端显式传参 → 网关鉴权与依赖闭包解析 → 运行快照冻结 → Worker 按快照加载”的链路，确保模型实际调用的是用户指定的智能体与技能，而非模型自主推断。

整体策略为一次规划、分批可回滚交付，首版即满足“新对话页真绑定 + 资产补齐 + 超管可改 + 运行时可验证”。

## User Stories

### 新对话页绑定

1. 作为首次登录的普通用户，我想在新对话页看到三个场景 Tab 和每个场景下的分组，以便快速知道平台能做什么。
2. 作为普通用户，我想点击一个场景 Tab 后看到该场景下的所有分组，以便按需选择。
3. 作为普通用户，我想点击一个分组后看到该分组下的任务列表，以便了解该分组支持的具体任务。
4. 作为普通用户，我想点击一个分组后该分组高亮且在输入框内以可删除标签形式回显，以便确认当前选择。
5. 作为普通用户，我想点击一个任务后输入框自动填入该任务的提示语模板并高亮待填部分，以便直接修改后发送。
6. 作为普通用户，我想在已输入内容时点击任务，系统弹出确认框让我选择覆盖或追加，以便不意外丢失已写内容。
7. 作为普通用户，我想点击分组标签的关闭按钮取消分组选择并清空关联的任务、任务标签与提示语，以便重新选择。
8. 作为普通用户，我想点击任务标签的关闭按钮仅取消任务选择而保留分组，以便微调任务。
9. 作为普通用户，我想切换场景 Tab 时若已选分组不属于新场景则自动清空分组与任务选择，以便不产生跨场景的非法组合。
10. 作为普通用户，我想在仅选分组不选任务时也能发送消息且仅绑定智能体，以便复用智能体但不指定技能。
11. 作为普通用户，我想在仅选任务不选分组时也能发送消息且仅绑定技能，以便快速调用技能而不限定智能体。
12. 作为普通用户，我想在未作任何选择时也能正常发送消息，以便退化为普通对话。
13. 作为普通用户，我想在选中分组后，技能弹窗与斜杠补全仅展示与该智能体相关的技能，以便快速从该智能体的能力中选择而不被无关技能干扰。
14. 作为普通用户，我想在选中分组时看到提示“已选智能体，技能列表已过滤为该智能体的可用技能”，以便理解过滤原因。
15. 作为普通用户，我想在取消分组选择后技能弹窗恢复展示全量技能，以便重新单独调用任意技能。
16. 作为普通用户，我想发送消息后欢迎态自动收起并进入对话态，以便看到执行过程。

### 标签与命名

17. 作为普通用户，我想分组标签与任务标签样式有区分（如颜色或图标），以便一眼分辨当前选中的是分组还是任务。
18. 作为普通用户，我想任务标签的文本与后台所选技能名称保持一致，以便所见即所得，确认将调用的技能。
19. 作为普通用户，我想批量新建的智能体名称与前端分组显示名称一致（如“办公文档”“数据分析”），以便在智能体列表与场景入口之间无缝对应。

### 可见性与权限

20. 作为普通用户，我想仅看到我有权限的分组与任务，无权限条目直接不展示，以便不被不可用选项干扰。
21. 作为只读用户，我想同样遵循可见性规则，不看到私有资源绑定的条目。
22. 作为部门管理员，我想看到本部门的公开与部门可见资源绑定的条目。
23. 作为超管，我想在管理后台看到所有条目含已禁用项，以便治理。

### 管理后台

24. 作为超管，我想在管理后台看到按场景分组的三 Tab 配置页，以便分场景治理。
25. 作为超管，我想在每个分组卡片上修改其绑定的智能体、显示名称、排序与启用状态。
26. 作为超管，我想在每个任务行上修改其绑定的技能（支持多选）、提示语与启用状态，且任务标签所展示的技能名称与此处配置一致。
27. 作为超管，我想保存修改后 30 秒内新对话生效，且不影响已在进行的对话。
28. 作为超管，我想对不合法的绑定（如公开智能体绑私有技能）收到可见性闭环校验错误。
29. 作为超管，我想所有绑定变更写入审计日志，以便追溯。

### 智能体资产

30. 作为新用户，我想 12 个分组均有对应智能体且默认公开，无需管理员额外操作即可使用。
31. 作为用户，我想每个智能体的人设、名称与技能与其分组语义及前端显示一致，且其技能列表与前端该分组下的任务所需技能一致，以便通过智能体弹窗直接找到任务相关技能。
32. 作为超管，我想批量新增的智能体与现有智能体采用同一人格模板与配置规范，以便一致维护。
33. 作为开发者，我想智能体的技能列表在构建时即按 Pill→Chip→Skill 关系生成，避免后续手工二次绑定。

### 预装资源

34. 作为新用户，我想离线部署预装的 22 个技能、2 个智能体、1 个工作流均已公开，首次登录即可使用任意任务对应的能力。
35. 作为运维人员，我想保持离线部署预装技能清单不变，仅统一可见性为公开，避免离线包体积与内容漂移。
36. 作为运维人员，我想预装清单的变更通过版本化发布，内容未变时不产生新版本。
37. 作为开发者，我想新创建的资源仍默认私有，需走审批流才能升级为部门或公开，以保持权限收敛。

### 运行时保障

38. 作为用户，我想我通过场景入口指定的智能体与技能在运行时被确定性调用，而非由模型自主选择，以便结果可预期。
39. 作为开发者，我想通过运行快照与提示词注入验证当前运行实际加载的智能体与技能与用户选择一致。

### 历史与回溯

40. 作为用户，我想从历史对话列表点开一条由场景入口发起的对话时，能看到当时所用的分组、任务与技能信息。

## Implementation Decisions

### 模块划分

- **场景绑定配置模块**：负责场景分组与任务的持久化、校验与查询。封装“绑定是否合法”“当前用户是否可见”的判断逻辑，对外提供按场景分组的聚合查询接口。该模块为深模块，内部处理可见性闭环、依赖校验与排序，对外仅暴露简单的聚合查询与更新接口。
- **预装资源清单模块**：负责将盘上技能与智能体声明同步为权威资源。处理可见性同步与幂等发布，提供清单不变下可见性统一的能力。
- **新对话页编排模块**：负责欢迎态的选择状态、双标签回显、模板注入与提交时的上下文组装。内部协调分组与任务的选择状态与输入框状态，对外暴露当前绑定上下文。
- **输入框技能入口模块**：负责技能弹窗与斜杠补全的过滤展示。对外接收当前选中智能体的技能列表与任务标签所需信息作为过滤条件，内部自行处理过滤、光标、键盘与渲染。
- **标签展示模块**：负责分组与任务标签的渲染与交互。分组标签与任务标签样式区分，任务标签的文本来源于后台技能名称，保持前后端一致。
- **管理后台配置模块**：负责超管对绑定的增删改查与审计。复用现有的资源选择器与可见性影响分析能力。
- **智能体批量构建模块**：负责按 Pill→Chip→Skill 关系批量生成智能体的配置与人格。内部聚合某分组下全部任务的技能并去重，名称对齐前端分组显示名称，对外提供批量预置能力。
- **运行时保障模块**：负责将用户指定的智能体与技能从前端上下文传递到模型执行的全链路保障，包含网关解析、快照冻结与提示词注入。

### 关键接口与契约

- 新增聚合查询接口：返回按场景分组的三级结构（场景 → 分组 → 任务），已按调用者可见性过滤；无权条目不返回；每个任务携带其绑定的技能标识与展示名称。
- 新增管理接口：分组与任务的创建、更新、删除与启用开关，仅超管可调用；可见性不合法时返回闭环校验错误并拒绝写入。
- 消息提交扩展：在现有消息提交上下文中增加可选的智能体与技能标识；技能支持多值；智能体与技能可独立出现；选中分组时技能标识需落在该智能体的技能列表范围内。
- 线程元数据扩展：首条消息创建时将场景、分组、任务与绑定标识写入线程元数据，供历史回溯与路由。
- 智能体构建契约：新建智能体的标识与显示名称对齐前端分组的标识与显示名称；其技能列表等于该分组下全部任务所需技能的并集去重；技能弹窗的过滤条件即为该智能体的技能列表；任务标签的文本来源于技能名称。

### 数据模型

- 新增分组绑定表：记录场景、分组标识、显示名称、绑定的智能体、排序与启用状态；同一场景下分组标识唯一；显示名称与智能体显示名称保持一致。
- 新增任务绑定表：归属分组，记录任务标识、显示名称、提示语模板、绑定的多个技能、排序与启用状态；同一分组下任务标识唯一；显示名称与技能展示名称关联。
- 预装清单：保持 22 技能 + 2 智能体 + 1 工作流的清单不变，仅统一可见性为公开；智能体的技能列表按分组任务聚合生成，名称对齐分组显示名称。

### 架构决策

- 绑定关系采用归一化两表而非单表 JSON，便于对技能做关联校验与可见性连接查询。
- 绑定查询在服务端按调用者可见性过滤后返回，前端不再做二次权限判断，仅做空状态处理。
- 配置变更采用数据库持久化 + 短时缓存，兼顾运营灵活性与新对话的实时性；已在进行的对话快照不受影响。
- 智能体采用批量文件预置而非逐个对话式创建，保证 11 个新智能体的配置、名称与人格一致性，人格模板沿用现有规范；且构建时即按前端绑定关系聚合技能，使“智能体→技能”与“任务→技能”一致；名称对齐前端分组显示名称以降低认知成本。
- 选中分组后的技能入口采用过滤而非屏蔽：仅展示与该智能体相关的技能，避免二义性的同时保留任务级技能的快捷选择。
- 无权限条目采用“不展示”而非“置灰”，减少用户对不可用选项的困惑。
- 离线部署预装清单保持不变，仅统一可见性为公开，避免离线包内容漂移；新创建资源默认私有，符合“默认收敛、显式开放”的权限原则。
- 双标签采用分组与任务分离的独立状态，任务标签的文本来源于技能名称，保证前后端一致性；样式上通过颜色或图标加以区分。

### 运行时调用保障

为确保模型实际调用的是用户指定的智能体与技能，而非模型自主推断，采用以下链路：

1. **前端显式传参**：新对话页在提交消息时将 `agent_name` 与 `skill_names` 作为结构化上下文与消息一同发送；该上下文与提示语文本双重传递，结构化参数为权威依据。
2. **网关鉴权与依赖闭包解析**：网关接收到上下文后，以调用者身份通过资源服务解析智能体与技能的可见性与依赖闭环，拒绝不可见或闭环不合法的组合；解析通过后进入运行创建流程。
3. **运行快照冻结**：创建运行时将解析得到的智能体版本、技能版本与依赖闭环固化到运行快照；后续执行不再按名称重新猜测定义，即使配置在运行期间变更，已启动的运行仍使用冻结版本。
4. **Worker 按快照加载**：执行器仅按快照中的版本加载智能体的配置与人格、技能的定义与提示词，不重新按名称加载最新版。
5. **提示词注入**：智能体的人格与技能描述通过提示词模板注入到模型上下文；技能的可用性通过提示词中的技能清单与工具声明体现，模型在该约束范围内选择工具调用。
6. **可观测性**：运行快照与提示词中均可追溯实际加载的智能体与技能版本，便于通过运行记录验证“所选即所得”。

### 交互细节

- 场景 Tab 默认不自动选中分组，仅展示分组列表；分组选中前不产生任何绑定，技能弹窗展示全量。
- 选中分组后，技能弹窗与斜杠补全的候选列表过滤为该智能体的技能列表，并提示“已过滤为该智能体的可用技能”。
- 点击任务后，除填入提示语模板外，在输入框内新增一个任务标签；任务标签与分组标签并列展示但样式区分，任务标签文本与后台技能名称一致。
- 任务的提示语模板支持占位符高亮，未输入时直接填入，已有输入时弹确认框。
- 标签的关闭行为：关闭任务仅清任务与任务标签，保留分组与分组标签；关闭分组则同时清分组、任务、双标签与模板，并恢复技能全量展示。

## Testing Decisions

### 测试原则

- 仅测试外部可观察行为，不测试内部实现细节。前端测试关注用户可见的渲染、交互与网络契约；后端测试关注接口的输入输出、权限与可见性语义。

### 需测试的模块

- **场景绑定配置模块**：需测试可见性过滤、闭环校验、外键约束与排序语义。
- **新对话页编排模块**：需测试选择、切换、双标签回显、模板注入与提交上下文组装。
- **输入框技能入口模块**：需测试选中分组前后的过滤显隐与提示。
- **标签展示模块**：需测试分组与任务标签的独立渲染、样式区分与删除行为，以及任务标签与技能名称的一致性。
- **管理后台配置模块**：需测试超管的增删改查与审计写入。
- **智能体批量构建模块**：需测试分组任务技能聚合去重、名称对齐与可见性一致性。
- **运行时保障模块**：需测试指定智能体与技能的快照冻结与提示词注入。
- **预装清单模块**：需测试清单不变下可见性统一与幂等发布。

### 现有测试参照

- 后端的资源可见性、依赖闭环与权限矩阵测试可作为新绑定的参照，复用其对公开/部门/私有的分区校验模式。
- 前端的场景钩子与瀑布栏组件单测、欢迎态端到端冒烟测试可作为新交互的参照，复用其对选择态与模板注入的断言方式。
- 管理后台的部门与资源管理页测试可作为新配置页的参照，复用其对超管守卫与表单提交的测试模式。

### 验收方式

- 后端对绑定配置的可见性与闭环校验提供单元与契约测试。
- 前端对选择、过滤、双标签与提交上下文提供单元测试，对新对话的端到端链路提供冒烟测试。
- 智能体的技能聚合与名称对齐提供一致性测试，预装清单提供可见性与幂等性测试。
- 运行时保障通过快照内容与提示词的断言进行验证。

## Out of Scope

- 会话中途切换智能体或技能。
- 工作流、渠道或子智能体类型的绑定。
- 引导式新手教程或埋点验证。
- 新增大模型供应商或模型能力扩展。
- 术语全量人话化与执行过程可读性优化（已在独立计划中）。
- 对工具资源的预装与治理变更。
- 离线部署预装技能清单的增删。

## Further Notes

- 本 PRD 已通过深度访谈收敛，关键分歧（过滤式互斥、双标签回显且任务标签与技能名称一致、名称对齐、无权限不展示、超管可运营、批量文件创建、预装清单不变仅统一公开、智能体构建时按前端绑定聚合技能、运行时快照保障）均已确认。
- 实施顺序建议：先完成 11 个智能体的批量补齐（构建时即聚合技能且名称对齐）与预装可见性统一，再完成绑定关系的持久化与接口，最后完成前端绑定（含双标签与过滤）与管理后台；每阶段独立可回滚。
- 预装清单保持 22 技能 + 2 智能体 + 1 工作流不变，新增的 11 个智能体追加后预装总数为 36 项，全部公开。
- 绑定变更不影响已创建对话的快照，仅对新对话生效，符合运行快照的冻结语义。
- 功能开关保留，关闭后新对话页退化为仅文本注入模式，便于紧急回滚。
- 运行时保障的可观测性通过运行快照与审计日志实现，便于问题定位与回归验证。
