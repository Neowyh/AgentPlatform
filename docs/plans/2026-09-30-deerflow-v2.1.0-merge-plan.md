## 4. 长期上游跟进策略（双轨制，已确认）

### 4.1 收敛轨（正式同步）

- **锚点**：上游 minor tag（2.0.0→6 月、2.1.0→9 月，约季度节奏）。
- 每轮完整走 Phase 0–5 流程，产出独立的 `docs/upgrades/deerflow-vX.Y.0/` 档案。
- tag 之间的 main 提交（如当前落后的 302 个）不进收敛轨，避免无 release
  门槛的变更放大回归面。

### 4.2 修复轨（定向 cherry-pick）

- 仅两类提交可 cherry-pick 进 develop：安全修复、阻断性缺陷修复。
- 每次 cherry-pick 在根台账登记（来源 SHA、原因、随下轮收敛自然吸收），
  与 harness 补丁同等巡检纪律。
- 业务选择性地把 tag 间想要的新特性留到收敛轨，不做特性级 cherry-pick，
  防止半成品依赖链。

### 4.3 补丁卫生（控制长期吸收成本的杠杆）

- **预算约束**：harness 本地补丁面维持在 ≤44 文件（10-01 当前值，原 40 已被
  fault-zeroing 合法突破；新补丁必须登记后才计入预算）；
  新企业行为一律走 `backend/app/` 控制面或 `agentplatform-extension` seam。
- **每轮收敛强制 reassess** PATCH-002..015 移除条件（Phase 3 已内建）。
- **上游化候选**（把本地补丁推回上游，彻底消除重放成本）：
  - PATCH-003（config/AGENTS.md 文档行）：上游已认领方向，可直接提 PR；
  - PATCH-011（SQLite 异步驱动 connect 桥）：通用缺陷，适合上游 PR；
  - PATCH-014 的 inspector-guarded 迁移保护：对上游多链路用户也有价值。
- 台账唯一权威化（Phase 0.3）后，`scripts/check-runtime-boundary.sh` 的
  基线数字同步更新，防止未登记 diff 回潮。

### 4.4 内网特性防线（每轮收敛不变的验收底线）

- `config.intranet.yaml` overlay 完整性（默认值覆盖、无公网 API 依赖）；
- offline bundle 构建 + `check-intranet.sh` 全绿 + 容器栈冒烟；
- 社区集成路径默认不可见/不可调用（PATH_POLICY 既定纪律）；
- `/api/resources` 唯一 canonical、本地导航与品牌不回退。
