## 二、三视角文档需求分析与差距

### 视角 A：新开发者（开发）

| 需求 | 现有覆盖 | 差距评估 |
|------|----------|----------|
| 项目概述与架构理解 | ✅ README + backend/README + frontend/AGENTS.md 架构图 | **差距小**，但缺少统一的架构全景图（backend 和 frontend 架构图分散在不同文件） |
| 本地开发环境搭建 | ✅ CONTRIBUTING.md + Install.md + CLAUDE.md | **差距小**，多处重复但一致 |
| 代码导航（源码结构） | ✅ backend/CLAUDE.md + frontend/AGENTS.md 详细描述 | **差距小** |
| 开发工作流（分支/提交/PR） | ✅ CONTRIBUTING.md + backend/CONTRIBUTING.md | **差距小** |
| 测试指南 | ⚠️ AGENTS.md 提到但简略，docs/testing-guidelines.md 存在但与实际测试框架脱节 | **中等差距**：缺少"如何写一个新的 backend test"和"如何写一个新的 frontend E2E test"的 step-by-step 教程 |
| API 开发参考 | ✅ backend/docs/API.md 详尽（665 行） | **差距小** |
| 认证系统理解 | ✅ backend/docs/AUTH_DESIGN.md + AUTH_UPGRADE.md | **差距小** |
| 中间件/工具扩展指南 | ✅ backend/CONTRIBUTING.md 有架构扩展指南 | **差距小** |
| 前端组件开发指南 | ⚠️ frontend/AGENTS.md 有架构但缺少组件开发模式文档 | **中等差距**：无 Shadcn UI 使用模式、组件设计规范文档 |
| 数据模型/类型系统 | ❌ 缺少集中的类型定义文档 | **较大差距**：backend 和 frontend 各自的类型散落在代码中 |

## 三、差距总结

### 严重缺失（大差距）

| # | 缺失项 | 影响角色 | 优先级 |
|---|--------|----------|--------|
| 1 | **生产部署标准指南**（非离线场景的在线生产部署） | 运维 | 🔴 高 |
| 2 | **备份与恢复策略** | 运维 | 🔴 高 |
| 3 | **高可用/扩容方案** | 运维 | 🔴 高 |
| 4 | **CI/CD 流水线文档** | 运维+开发 | 🔴 高 |
| 5 | **版本迁移指南**（v1→v2、版本升级路径） | 部署用户 | 🟡 中 |

### 中等差距

| # | 缺失项 | 影响角色 |
|---|--------|----------|
| 6 | 前端组件开发规范（Shadcn UI 使用模式） | 开发 |
| 7 | 数据模型/类型系统集中文档 | 开发 |
| 8 | 测试 step-by-step 教程 | 开发 |
| 9 | 生产环境安全检查清单 | 运维 |
| 10 | 通用运维排障手册 | 运维 |
| 11 | 健康检查/监控集成文档 | 运维 |
| 12 | config.example.yaml 缺少逐字段注释 | 部署用户 |
| 13 | 常见错误码对照表 | 部署用户+运维 |

### 已有但可改进

| # | 项目 | 现状 |
|---|------|------|
| 14 | 后端/前端架构全景图 | 分散在不同文件，缺少统一视图 |

## 四、建议优先行动

1. **立即补充**：生产部署指南、CI/CD 文档、备份恢复策略（运维刚需）
2. **短期优化**：为 docs/ 目录创建统一索引 README，清理内部过程文档，统一中英文
3. **中期建设**：前端组件开发规范、测试教程、错误码手册、监控集成文档
4. **长期规划**：版本迁移框架、高可用架构文档、ADR（Architecture Decision Records）
