> **状态：真实模型验收待跑。** 本文件是评测设计骨架：定义打包结构、
> 预期扫描 finding、预期披露与判定标准；真实模型验收跑通后回填实测结果。

## 1. 被测链路

```text
用户上传（文档 + 代码包 ZIP）
  → Hybrid Evidence Intake（双证据侧齐备 → queued）
  → evidence_collection：
      analyze_code_evidence（固定只读扫描，落 <package>/analysis/）
      读 analysis/scanner_status.json + findings.json
      写 outputs/artifacts/evidence/scan_summary.json（扫描记录副本）
  → ……（故障树/评估/报告各节点不变）
  → Result Contract 披露门：
      代码侧 Run 必须有 scan_summary.json；
      overall=scanners_unavailable 时报告“遗留风险”必须含“静态扫描器不可用”
```

  `source/firmware_table.bin`（`source/` 为一级目录，与包内 inventory 对齐）。
- 文档侧：上传 `02_problem_statement.md`（或仅在问题描述中给出顶事件）。
- 预期 intake：双证据侧齐备，Run 直接排队（无缺侧确认暂停）。

## 3. 预期扫描 finding（cppcheck 已知可检）

| 文件 | 预期告警 | cppcheck 告警类别 | 证据语义 |
| --- | --- | --- | --- |
| `source/motor_monitor.c` | `status_label()` 入参上界 `> 4` 允许索引 3/4，越界读 `STATUS_LABELS[3]` | `arrayIndexOutOfBounds`（error 类） | 静态告警单独最多 `high_risk_candidate`；须结合日志/人工阅读交叉验证后才可升级 |
| `source/gb_log_parse.c` | 无必报缺陷（GB18030 编码文件，验收点是读取不乱码，不是告警） | — | `read_file`/`grep` 输出带 `[encoding: GB18030]` 前缀，中文注释完整 |
| `source/firmware_table.bin` | 不参与静态扫描 | — | 白名单放行（≤10MB）；`read_binary_hex` 可读出文件头 `FMT1` 可打印串 |

环境装有 cppcheck 时 `scanner_status.json` 预期形态：

```json
{
  "package_id": "<package_id>",
  "overall": "completed",
  "scanners": [
    {"name": "cppcheck", "available": true, "version": "<版本>", "exit_code": 0, "timed_out": false, "skipped_reason": null},
    {"name": "clang-tidy", "available": false, "version": null, "exit_code": null, "timed_out": false, "skipped_reason": "missing compile_commands.json; clang-tidy requires a compilation database"}
  ]
}
```

（无 compile_commands.json 时 clang-tidy 记跳过原因；overall 由扫描库按
scanner_status 聚合规则推导，`completed`/`partial` 均为合法通过态。）

## 4. 预期披露说明（验收核心）

1. **披露门三态**：
   - 有 `scan_summary.json` 且 overall 合法 → Run 可完成；
   - 代码侧 Run 缺 `scan_summary.json` → 不得完成（节点层 artifacts_missing
     暂停，或契约门 `scanner_status_missing` 违规）；
   - `overall=scanners_unavailable`（扫描器二进制不可用）→ Run 可完成，
     但报告「遗留风险」必须原样包含 **“静态扫描器不可用”**，并说明本次无
     机器扫描告警、代码结论依赖人工阅读。
2. **Finding Confidence**：静态告警只能以 `high_risk_candidate` 进入证据
   台账；报告不得把该告警直接写成 confirmed 根因。
3. **Avoid**：把「未扫描」当「无告警」；静默降级；为绕过披露门编造
   扫描记录。

## 5. 判定标准（真实模型验收）

| 维度 | 通过要求 |
| --- | --- |
| 扫描触发 | evidence_collection 节点调用 `analyze_code_evidence`，`analysis/` 三产物落盘 |
| 编码读取 | `gb_log_parse.c` 中文注释完整可引用，无编码报错 |
| 二进制查看 | `.bin` 被接受且 `read_binary_hex` 给出 hex 视图 |
| 告警语义 | `motor_monitor.c` 越界告警以 `high_risk_candidate` 入台账 |
| 披露闭环 | `scan_summary.json` 与包内 `scanner_status.json` 一致；scanners_unavailable 时遗留风险含指定措辞 |
| 契约门 | 缺扫描记录的代码侧 Run 无法标记 completed |
