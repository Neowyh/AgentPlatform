# Findings

- Active branch is `refactor/workflow-module`, with Phase 1 committed as `2e82fa29`.
- The approved plan identifies `WorkflowExecutor`, `WorkflowStore`, worker/event routes, and `useRunStatus` as the main boundaries.
- GitNexus was initially one commit behind this worktree; re-analysis completed before impact analysis.
- SQLite returns `DateTime(timezone=True)` lease values without tzinfo. The task-finishing guard compared that value directly with `datetime.now(UTC)`, producing a TypeError before it could enforce ownership. SQL lease checks already avoid this Python boundary.
- The approved Phase 2 acceptance is stricter than the current progress notes: it also requires immutable per-run ownership (not only workflow visibility), auditable limit failures and lease changes, and a real two-worker takeover proof. The current router authorizes run access through workflow metadata, so a public/department workflow does not yet isolate individual runs by `created_by`.
- `useRunStatus` has SSE reconnect mechanics but no hook-level test for its replay cursor or polling fallback; the existing reducer test only proves token accumulation and a terminal event. The durable backend tests already use a SQLite `WorkflowV2Store` fixture and are the right place for a two-worker takeover proof.
- A task row cannot prove lease governance after a takeover because it stores only the current owner. Phase 2 now has append-only `workflow_lease_audit` records for claim, takeover, and release. Loading the task ORM object before a SQLite CAS update requires `synchronize_session=False`; otherwise SQLAlchemy compares the driver-returned naive timestamp with an aware timestamp in Python.
- Event limits must be a database predicate, not a read-then-append check: concurrent workers/actions can otherwise both observe capacity. Ordinary events now reserve one final sequence slot, allowing the worker to persist an auditable terminal failure when the normal event budget is exhausted.
- Attempt exhaustion is a worker-side terminal path, so it bypasses the application worker's exception handler. `claim_next_task` must itself append a `run_failed` event while moving the run to `failed`; otherwise an SSE client sees no explanation for a permanently unclaimable task.
- The parser's `max_iterations` validation alone did not constrain the compiled LangGraph. The compiler now inserts internal gate nodes on every edge that closes a graph cycle; each gate merges a per-edge durable counter into graph state and raises `workflow_iteration_limit_exceeded` with a `node_failed` event when its declared bound is exceeded.
